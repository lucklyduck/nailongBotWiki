编译奶龙固件

1. 简介​

本教程使用 NaiFirmware，基础版本 2.4.2、ESP-IDF v5.5.5、板型变体 nailong-otto。主要定制是四舵机无手臂、“你好奶龙”唤醒、9 张彩色图片、5 秒笑声和组合动作。

当前源码还含语音停止与 BOOT 继续监听的候选修订。哪些已经实测，先看 功能状态。

获取源码

NaiLongFirmware 同时提供固件和配套 server。下面使用公开版的 nailong-firmware/ 目录；可直接烧录的发布包仍待发布。

2. 准备环境​

  1. 安装并激活 ESP-IDF v5.5.5，终端执行 idf.py --version 核对。
  2. Windows 建议使用短英文路径，例如 C:\work\NaiLongFirmware。
  3. 保留源码包里的 Materials/、nailong-firmware/ 和依赖锁定文件，首次构建需要联网下载组件。
  4. 使用已准备好的 nailong_assets/ 时不用重新转换素材；需要重新准备音频时再安装 ffmpeg。
NaiLongFirmware/
├── Materials/                         原始素材
├── nailong-firmware/                   在这里执行固件构建命令
│   ├── scripts/build_nailong.py
│   ├── scripts/prepare_nailong_materials.py
│   ├── main/boards/otto-robot/
│   └── dependencies.lock
├── xiaozhi-esp32-server/                配套语音服务端
└── docs/                               快速开始与验证说明

3. 编译公开配置​

在已激活 ESP-IDF 的终端获取源码并进入固件目录：

git clone https://github.com/cccatnipent/NaiLongFirmware.git
cd NaiLongFirmware/nailong-firmware
python scripts/build_nailong.py

已经下载源码包时，直接进入 nailong-firmware/ 执行最后一条命令。脚本选定中文、nailong-otto、自定义唤醒词和配套资源；公开版已移除个人身份覆盖，每台设备使用自己的原厂 MAC 和 UUID。

不带参数时使用 xiaozhi.me 的默认 OTA 地址。自建后端时用 --ota-url 指定地址，见 更换服务端。

项目当前设置
芯片 / 内存ESP32-S3，16 MB Flash，Octal PSRAM
唤醒词ni hao nai long / 你好奶龙，阈值 10%
图片 / 音频nailong_assets/ 中的场景图片和 5 秒笑声
最新候选功能本地停动作、BOOT 打断后继续监听

会看到什么：结尾出现 Project build complete，并生成 build/xiaozhi.bin、build/generated_assets.bin 和烧录地址表。构建失败就先看错误，不要用残留镜像继续烧录。

4. 烧录和看日志​

把 COM5 换成实际串口：

idf.py -p COM5 flash monitor

macOS / Linux 使用实际的 /dev/cu.… 或 /dev/ttyACM…。按 Ctrl+] 退出日志。

完整烧录会按地址表更新引导、分区、应用和资源。只写应用不会更新图片、笑声或唤醒阈值。已有设备升级时，按发布包说明选择写入范围，见 导出合并镜像。

5. 验证​

检查预期
启动无持续重启，屏幕正常，能配网
唤醒“你好奶龙”进入对话，日志中的模型阈值为 0.1
图片待机图正常，回答时换图，大笑时显示大笑图
笑声self.otto.laugh 播放约 5 秒；看实际工具调用和声音
动作先校准，再用少步数、小幅度测试
候选功能单独记录边笑边走、语音停动作、BOOT 后继续提问的实测结果

6. 常见问题​

现象解决
找不到 idf.py使用 ESP-IDF 终端，确认版本 v5.5.5
首次构建卡在下载检查组件下载网络，保留依赖锁定文件
编译成了原版 Otto使用 python scripts/build_nailong.py，核对变体 nailong-otto
图片不对或阈值还是旧值配套更新 generated_assets.bin，不要混用旧资源
提示素材缺失核对源码包的素材目录，见 更换表情
编译成功但设备不正常看 串口日志，编译成功不等于实机通过
