FreeRTOS：奶龙怎么同时听、说、动

1. 一句话理解​

FreeRTOS 让一块芯片能「同时」做好几件事：它把工作分给几个任务，飞快地轮流执行，忙的、急的先干。

奶龙一边走路，一边还能听你说「停下」，靠的就是它。小智固件跑在 ESP-IDF 自带的 FreeRTOS 上，ESP32-S3 有两个核，所以有时真的是两个任务同时在跑。

奶龙说

把我想成一个有好几个小脑袋的奶龙：一个专门听，一个专门说，一个专门管腿。小脑袋之间靠传纸条（队列）和举旗子（事件组）商量事情。

2. 五个词就够了​

词打个比方奶龙里的例子
任务一个小脑袋，只管一件事「听」的任务、「动腿」的任务
优先级谁更急谁先干，数字越大越急听你说话最急（8），动腿不急（3）
队列排队的纸条箱，先放先取大模型说「跳舞」，就往动作箱里放一张纸条
事件组一排小旗子，举起哪面就有人去处理听到「你好奶龙」就举起「唤醒」旗
栈每个小脑袋的草稿本，写满了就会出错写新任务时要给够大小

3. 奶龙的几个小脑袋​

任务负责急不急
听（audio_input）一直听麦克风，等「你好奶龙」最急，晚一点就会漏听
说（audio_output）把声音送到喇叭比较急
大脑（main_event_loop）管现在是待机、在听还是在说，和服务器收发消息一般
腿（otto_action）按动作箱里的纸条转舵机一般，比听和说都低
音效（otto_sound）放动作音效一般
压缩（opus_codec）把声音压缩 / 解压，方便上网传最不急

为什么腿要比听和说「不急」？源码里写着原因：说话和音效必须能打断舵机，不然走路时声音会一卡一卡的。

4. 「跳个舞」是怎么传到腿上的​

  1. 大模型决定让奶龙跳舞，调用工具 self.otto.swing。
  2. 「大脑」收到后，不自己去转舵机，只往动作箱里放一张纸条，马上回去干别的。
  3. 「腿」从箱子里取出纸条，慢慢转舵机，跳完回到站立姿势。
  4. 这期间「听」一直在工作，所以你随时能说「停下」。说「停下」会清空动作箱。

这就是 添加新动作 里说「动作在单独的任务里执行」的意思。

5. 写代码时记住三条​

规矩为什么
MCP 工具里别做耗时的事，放进队列交给别的任务卡住「大脑」，就收不到服务器消息了
等待用 vTaskDelay(pdMS_TO_TICKS(毫秒))，别写空循环空循环不让别人干活，还会触发看门狗重启
新任务的栈给足，一般从 4 KB 起草稿本写满了会直接重启

6. 看到这些报错怎么办​

串口日志里意思怎么办
A stack overflow in task xxx任务 xxx 的草稿本写满了调大它的栈
Task watchdog got triggered有个任务一直不让出 CPU找死循环，循环里加 vTaskDelay
Guru Meditation Error程序崩了用 idf.py monitor 看回溯，它会告诉你哪一行
奶龙说

看到「stack overflow」别慌，给那个小脑袋换个大点的草稿本就好。

7. 想深入再看​

完整任务表（优先级、栈、核、源码位置）

从 ~/otto 源码里的 xTaskCreate 逐个找出来的：

任务名优先级栈核源码
audio_input86 KB0 号核audio/audio_service.cc
audio_output44 KB不固定同上
main_event_loop38 KB不固定application.cc
otto_action33 KB不固定boards/otto-robot/otto_controller.cc
otto_sound34 KB不固定同上
opus_codec226 KB不固定audio/audio_service.cc

注意：ESP-IDF 里栈大小的单位是字节，和原版 FreeRTOS（单位是字）不一样。系统节拍 CONFIG_FREERTOS_HZ=100，一个 tick 是 10 ms。

开机顺序
  1. 引导程序加载固件，FreeRTOS 启动，在 main 任务里调用 app_main()。
  2. app_main()（main/main.cc）初始化 NVS（存 Wi-Fi 和设置），然后调用 Application::Start()。
  3. Start() 依次：初始化屏幕和音频、创建上面那些任务、连 Wi-Fi、检查 OTA 拿服务器配置、选 通信协议、播放提示音。
  4. app_main() 返回，之后全靠各个任务干活。

设备状态一共 11 种（main/device_state.h）：未知、启动中、配网中、待机、连接中、聆听、说话、升级中、激活中、音频测试、致命错误。

主循环代码：事件组 + Schedule()

「大脑」大部分时间在睡觉，等事件组里的旗子：

auto bits = xEventGroupWaitBits(event_group_, MAIN_EVENT_SCHEDULE |
    MAIN_EVENT_SEND_AUDIO | MAIN_EVENT_WAKE_WORD_DETECTED |
    MAIN_EVENT_VAD_CHANGE | MAIN_EVENT_CLOCK_TICK | MAIN_EVENT_ERROR,
    pdTRUE, pdFALSE, portMAX_DELAY);

别的任务想改状态或发网络消息，不能直接动，要用 Schedule() 把代码交给「大脑」执行：

void Application::Schedule(std::function<void()> callback) {
    {
        std::lock_guard<std::mutex> lock(mutex_);
        main_tasks_.push_back(std::move(callback));
    }
    xEventGroupSetBits(event_group_, MAIN_EVENT_SCHEDULE);
}

这样状态只有一个任务在改，不会乱。

动作队列代码

放纸条（MCP 工具回调里）：

OttoActionParams params = {action_type, steps, speed, direction, amount};
xQueueSend(action_queue_, &params, portMAX_DELAY);

取纸条（otto_action 任务里）：

if (xQueueReceive(controller->action_queue_, &params, pdMS_TO_TICKS(1000)) == pdTRUE) {
    // 执行动作，结束后回到站立姿势
}

动作箱最多放 10 张纸条；音效箱只放 1 张，新的来了旧的就丢掉。self.otto.stop 会先停下当前动作，再用 xQueueReset 清空动作箱，最后放一个「站好」的动作。

打印每个任务的 CPU 占用

application.cc 主循环里留了两行，默认注释掉：

// SystemInfo::PrintTaskCpuUsage(pdMS_TO_TICKS(1000));
// SystemInfo::PrintTaskList();

去掉注释重新编译，串口每 10 秒打印一次任务列表和 CPU 占用。奶龙的 sdkconfig 已经打开了需要的选项，不用另外改。
