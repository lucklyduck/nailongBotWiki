七、后续发布与回退参考（供获授权的维护人员）

下面是后续版本的操作参考，不是已经执行的新发布。先完成本地预览和 npm run build。
将 source/build/ 的内容放入交接包根目录 site/，避免把目录嵌成 site/build/。
上传新版本的 site/、Dockerfile 和 nginx.conf 到新的 releases/<版本号>/ 目录，保留现有版本。
服务器进入新目录，构建新的唯一标签，例如：

sudo docker build -t nailong-wiki:ui-20261103-v1 .
sudo docker run --rm nailong-wiki:ui-20261103-v1 nginx -t

不要覆盖当前生效的 /opt/nailong-wiki/nginx/default.conf，尤其是后续已经配置 HTTPS 后。
可先用仅本机可访问的预览端口测试新镜像，再安排正式切换：

sudo docker run -d --name nailong-wiki-preview -p 127.0.0.1:18080:80 nailong-wiki:ui-20261103-v1
curl -I http://127.0.0.1:18080/

测试后停止并删除此次临时预览容器。正式切换需要短暂中断，请由维护人员执行：停止当前容器、将其改为独立备份名称、使用新镜像创建同名 nailong-wiki 容器，并保留上述三项挂载、80/443 端口映射、健康检查、自动重启与日志轮转设置。
如果新容器验证失败，停止并移除新容器，将刚备份的容器恢复原名称并启动。删除任何容器前确认名称，不要删卷、镜像历史或系统快照。

当前另有一个停止的 nailong-wiki-before-domain 容器，只是域名准备前的回退版本，并非 UI 新版本备份；不要误启动与现有容器争用端口。

常用只读检查（登录服务器后）：
sudo docker ps --filter name=nailong-wiki
sudo docker logs --tail 100 nailong-wiki
sudo docker inspect --format='{{.State.Health.Status}}' nailong-wiki
sudo docker exec nailong-wiki nginx -t
