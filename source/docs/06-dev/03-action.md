## 1. 简介

先跑通“模型参数 → 动作队列 → 舵机方法”，再写新轨迹。NaiFirmware 通过统一工具 `self.otto.action` 选择动作，不需要每个动作新增一个 MCP 工具。

## 2. 先加一个动作别名

打开 `main/boards/otto-robot/otto_controller.cc`，在解析 `action` 的分支中，紧挨 `swing` 加入：

~~~cpp
else if (action == "my_swing") {
    QueueAction(ACTION_SWING, steps, speed, 0, amount);
    return true;
}
~~~

这只是给现有摇摆加一个名字，复用真实的队列和轨迹。同步修改工具描述，让模型知道 `my_swing` 的含义和参数。

本例是开发练习，尚未作为发布功能上机验证。

## 3. 再写新轨迹

| 改哪里 | 做什么 |
|---|---|
| `otto_movements.h/.cc` | 增加动作方法，复用现有舵机插值或振荡方法 |
| `otto_controller.cc` 的动作枚举 | 加一个不重复的动作编号 |
| 动作任务分支 | 调用新方法，并沿用归位处理 |
| `action` 参数分支和描述 | 将新名称映射到新编号 |
| 取消检查 | 参考当前 `IsCancelled()` 路径，让长动作能停止 |

从已有 `Swing`、`Bend` 等方法的小改动开始。动作循环、插值和长等待都要响应取消，不能只在开始前检查一次。

## 4. 编译和实测

1. 按 [编译奶龙固件](/docs/flash/build) 构建并烧录。
2. 机器人架空，先测试少次数、小幅度、慢速度。
3. 看模型是否调用正确参数，再检查实际方向和归位。
4. 中途请求停止，核对停止后不再继续写入旧轨迹。

:::warning
不要把语音停止当作机械急停。听到舵机持续嗡鸣、发现碰撞或堵转，立即关闭电源并检查。
:::

## 5. 常见问题

| 现象 | 检查 |
|---|---|
| 模型说动作不支持 | 工具描述和名称分支是否同时更新 |
| 编译成功但没有动作 | 编号、任务分支、引脚和队列是否对应 |
| 停止后又继续动 | 是否遗漏循环、插值或等待中的取消检查 |
| 新动作容易摔倒 | 先检查校准，再缩小幅度、降低速度 |
