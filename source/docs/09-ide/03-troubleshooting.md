## 1. 三种成功不是一回事

| 阶段 | 去哪里看 | 完成标志 |
|---|---|---|
| 编译成功 | 任务管理器的本次 Build | 成功、退出码 0 |
| 烧录成功 | 本次 Flash | 成功、退出码 0，工程与端口正确 |
| 运行正常 | 监视器 | 新文字出现、心跳持续增加 |

Agent 的回答和预期输出是线索，实机日志才说明设备运行了什么。

## 2. 出错先找这三样

1. **本次任务日志**：在“最近任务结果”点“查看”，保留末尾报错。
2. **工程和操作**：记录工程名、编译还是烧录、所选端口。
3. **新串口输出**：清空旧接收内容，需要时复位，再看有没有新日志。

交给 Agent 分析时，把这三样一起说明，不要只说“失败了”。截图和日志先遮蔽 Key、密码与个人信息。

## 3. 常见问题

| 现象 | 先检查 |
|---|---|
| 工程列表没有示例 | 发布包是否包含示例，工程是否在直接子目录下 |
| 一直等待编译 | 是否选了工程，上一次任务是否结束 |
| 刷新设备后没有端口 | 数据线、USB 口、供电、系统设备识别 |
| 烧录失败 | 串口选错、端口被占用、设备没进入下载模式 |
| 烧录成功但没输出 | 同一端口、115200 8-N-1、已打开串口，必要时复位 |
| 输出乱码 | 波特率和文本编码 |
| 改了代码却还是旧文字 | 保存文件、重新编译、再烧录，核对新 Flash 时间 |
| 只有 Agent 说成功 | 查看任务记录，并打开监视器验证 |

## 4. 一页速查

| 第一次运行 | 改动后运行 |
|---|---|
| 选示例工程 → 编译 | 改两处文字 → 保存 → 编译 |
| 刷新设备 → 选 COM → 烧录 | 核对端口 → 再烧录 |
| 监视器 → 看 Hello World 心跳 | 清空旧日志 → 看新文字心跳 |

这两遍都跑通后，再进入 [奶龙固件开发](/docs/dev)。不要把普通示例的 SDK 或烧录地址直接套用到奶龙工程。
